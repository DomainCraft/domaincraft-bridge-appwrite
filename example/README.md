# Demo Shop — Appwrite

Demo e-commerce API used to benchmark DomainCraft vs hand-written code

Generated by the `domaincraft-bridge-appwrite` bridge: one `appwrite.config.json`
with the whole schema. Migrations are run by the Appwrite CLI v26 — the bridge writes
no migration scripts and no server code.

## Quick start

```bash
# 1. Bind to your project
appwrite client --endpoint https://cloud.appwrite.io/v1 --project-id <PROJECT_ID> --key <API_KEY>

# 2. Deploy (re-running is a no-op)
appwrite push all --force

# 3. Seed (only when the model has seed)
node scripts/seed.js
```

`domaincraft generate --migrate` chains generate + deploy — bind first (step 1),
or the push has no project to target.

> Don't run `appwrite init project` here — it clobbers this schema. Prefer a login
> session over an API key? `appwrite login`, then set `projectId`/`endpoint` in the file.

⚠️ **`push` treats the config as the full list.** Databases and tables that exist
in the project but not in the config will be **proposed for deletion**. Don't push
into a project with data outside your domain model.

## Using the schema

- **Auth is native Appwrite** (email + password). The `User`
  entity is **not** created as a table — users live in Appwrite Auth. Relations to
  it become `varchar(36)` columns holding user IDs.
- **Assign a role on sign-up.** After creating a user, add them to a team:
  `teams.createMembership("role-user", [], email)`.
  Default role: **User**.
- **`@Owner` rows.** When creating a row, pass `rowPermissions("<table>", userId)`
  from `helpers/permissions.js` — Appwrite then filters `list` by row permissions.
- **Seed.** `SEED_USER_ID=<userId> node scripts/seed.js` (idempotent) — `@Owner`
  row permissions resolve to that user ID.
- **First admin.** Create a user in the Console and add them to the
  `role-admin` team (or via the API).

## Renames & data safety

| Change in `domain.yaml` | What `push` does | Data |
|---|---|---|
| field `old_name` | renames the column in place (`previousKey`) | preserved |
| entity `old_name` | keeps the table `$id`, updates its `name` | preserved |
| `required` / `default` / `size` / `min` / `max` / `elements` / `onDelete` | updates the column in place | preserved |
| `type` / `array` / `relatedTable` | recreates the column | **lost** (plan warns) |

**Entity rename** (`old_name`) pins the table `$id` to the old name, so `push`
updates the display `name` in place and rows survive. `old_name` is a *permanent*
`$id` pin: removing it changes the `$id` → delete+create → move rows manually
before pushing.

⚠️ Appwrite ≤1.9.5: renaming a column on a table with relationship columns fails
(index-rebuild bug). Workaround: recreate the table, or temporarily drop the
relationship → push → restore it.

Server: use `appwrite/appwrite:1.9.5` (1.9.6/`latest` were broken at the time of
writing — `exec format error`).

## Limitations

The bridge implements only what `appwrite.config.json` can express; everything else
becomes app-side logic or no-op fields.

| DomainCraft construct | In Appwrite |
|---|---|
| `decimal` | `float`/`double` (floating point — precision loss; store money as integer cents in `int`) |
| `json` / `jsonb` | `text` (JSON string) |
| `date` | `datetime` ISO 8601 (a time appears) |
| self-relation | `varchar(36)` parent ID, no FK (Appwrite issue #9471) |
| `default` on a required field | `required:false` + default (Appwrite forbids default on required) — column becomes nullable |
| audit / soft_delete / optimistic_lock | columns only, `required:false` — the server doesn't auto-fill; the app writes them |
| indexes on relationship columns | dropped from the index (TablesDB refuses); empty index omitted |
| `default: now()` / `uuid()` | static defaults only |
| `regex` / `hidden` / `readonly` | validation / semantics in the app |
| `gt` / `lt` (strict) | approximated by inclusive `min` / `max` |
| `on_delete: no_action` | `restrict` |
| roles with same lowercase slug | unsupported (`role-<lowercase>` — one team) |
| index type (btree / gin / …) | `key` (key / unique / fulltext only) |
| `event_sourced` / `cacheable` / `multi_tenancy` / `infrastructure` | ignored |

```bash
appwrite pull tables              # compare the schema with the server
appwrite types ./types            # type definitions from the live schema
appwrite generate                 # type-safe SDK for your project's language
```
